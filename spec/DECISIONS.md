## Раздел B (числа и поведение): подход
Мы не клонируем точное поведение оригиналов. Клонируем **функции**. Поэтому:
- диапазоны, дефолты и алгоритмы **проектируем сами** (`spec/brush-engine.md`, `spec/blend-and-color.md` и т.д.);
- где важна «похожесть ощущения» (стабилизатор, smudge, акварель), подбираем параметры на тестовом корпусе своих эталонных мазков;
- значит, обходим и юридический вопрос, и отсутствие доступа к приложениям.

## Раздел C (ассеты)
- Головы кистей и текстуры генерируются процедурно (шум, круги, щетина) скриптом из репозитория.
- Шрифты: несколько OFL из Google Fonts, лицензии лежат рядом.
- Иконки: Material Symbols (Apache 2.0) + свои.

## Инструменты разработки
- **Всё окружение локально в папке проекта:**
  - `.venv`: Python для скриптов генерации ассетов и тестовых эталонов;
  - `.tools/gradle`: GRADLE_USER_HOME;
  - `.tools/`: прочие загрузки (эмулятор, system image, при нужде NDK).
  - Существующий Android SDK в `%LOCALAPPDATA%\Android\Sdk` используется только на чтение (platforms, build-tools).
- Gradle wrapper 8.x, AGP 8.x, Kotlin 2.x, Compose BOM.
- Тесты:
  - JVM unit-тесты для ядра (модель документа, undo, формулы blend на CPU-референсе, flood fill, кривые, стабилизатор);
  - instrumented только при наличии эмулятора или устройства.
- Эмулятор: Android Emulator + system image API 34 x86_64 (ставится через sdkmanager, ~3 GB). Нужен для проверки GL.
